# Reels quotidiens @SkyElite

Chaque jour : 3 reels verticaux (1080×1920) d'empty legs **réels**, publiés sur la page
« SkyElite Reels » : https://claude.ai/artifact/QzP9Y8iKy3nSy7AZpmfeKE

Application SkyElite (catalogue des vols) : https://claude.ai/artifact/E3uurAWMhsGwNg3wjDeVLm

## Règles
- **Destinations européennes uniquement** : l'aéroport d'arrivée est en Europe (Suisse, UE, Royaume-Uni, Norvège, Balkans, Turquie européenne…). Le départ peut être ailleurs.
- **Date de départ du vol ≥ jour de publication + 7 jours** (heure de Suisse).
- Uniquement des vols **avec prix publié** par l'opérateur.
- Jamais deux fois le même vol (vérifier les reels déjà publiés dans la base `reels`).
- Varier les destinations : éviter une ville d'arrivée déjà utilisée dans les 7 derniers jours, et mélanger les régions.
- **Prix client (majoré)** : prix opérateur de l'avion entier converti en euros (1 USD ≈ 0,86 €, 1 CAD ≈ 0,62 €), **plus 200 €**, arrondi à la dizaine d'euros supérieure. C'est ce prix majoré qui s'affiche partout (vidéo « Vol entier », légende, site de réservation). Cofinancement dès = prix client ÷ nombre de places, arrondi à l'euro supérieur. Ne jamais afficher le prix opérateur ni le nom de l'opérateur au client (la source reste seulement dans la base `reels` et l'application interne).
- **Mise en avant du prix** : l'accent est mis sur le **prix du vol entier** (avion privatisé), avec en second la **possibilité de cofinancement à partir de** prix du vol ÷ nombre de places. La vidéo l'affiche ainsi automatiquement (« Vol entier 2 990 € » en grand, puis « Cofinancement possible dès 332 €/pers. » et « 9 personnes max »). La légende Instagram suit le même ordre, par exemple :
  « 💶 Vol entier : 2 990 € (avion privatisé, 9 places)
  🤝 Cofinancement possible dès 332 €/pers. (9 personnes max) »
- **Marque** : « @SkyElite » avec le logo est affiché au milieu à droite de la vidéo dès la première image et jusqu'à la fin (fixé dans le modèle, ne pas le retirer).
- **Une seule vidéo-source par reel, et une vidéo-source différente pour chacun des 3 reels du jour.** Tous les plans d'un reel viennent du même fichier (plusieurs passages de ce fichier sont permis). Sources possibles : les vidéos utilisables de `public/footage/drive-manifest.json` et de `public/footage/manifest.json` (plus une vidéo Pexels par reel si la clé existe). Choisir d'abord une source qui correspond à la destination, sinon celle utilisée le moins récemment (champ `footage` des documents de la collection `reels`). Une source doit offrir au moins 10 s de plans utilisables pour servir seule. S'il n'y a pas assez de sources distinctes pour les 3 reels, le reel sans source prend le fond animé (`clips: []`) : ne jamais réutiliser une source déjà prise ce jour-là, et signaler dans le résumé qu'il faut ajouter des vidéos dans le dossier Drive.
- **Toujours varier les images.** Avant de monter un reel, relire le champ `clips` des documents `reels` des 7 derniers jours (passages déjà pris : source, début, durée). Pour une source déjà utilisée, prendre en priorité les segments qui n'ont pas servi récemment (ou ceux utilisés le moins récemment), et ne jamais refaire le même enchaînement (mêmes passages dans le même ordre) qu'un reel précédent. Varier aussi l'ordre des plans, le plan d'ouverture et le cadrage (`zoom` entre 1 et 1,25 et `origin` différents, sans faire réapparaître un filigrane effacé). Entre deux jours consécutifs, ne pas ouvrir deux reels sur le même plan. Si une source n'a plus de passage neuf, choisir une autre source ; s'il n'en reste aucune, le signaler dans le résumé.
- Ne jamais inventer un vol : chaque reel cite la page source de l'opérateur.

## Étapes
1. `git fetch origin emptyleg-reel && git checkout emptyleg-reel`, puis `npm ci`.
2. Lire l'application (Artifact `read`) et extraire `REAL_ROWS` (départ, arrivée, date, heure, fin de fenêtre, appareil, places, prix, devise, prix catalogue, source).
3. Lire la base de la page Reels (`ArtifactData list`, collection `reels`) pour connaître les vols et villes déjà utilisés.
4. Garder les vols éligibles (règles ci-dessus). **S'il en reste moins de 6** : chercher de nouveaux empty legs réels vers l'Europe sur les pages publiques des opérateurs listés dans `SRC` de l'application et d'autres opérateurs européens (WebFetch), puis les ajouter à `REAL_ROWS` (et à `AP` si l'aéroport manque : nom, région, latitude, longitude). Vérifier le script avec `node --check` avant de republier l'application. Ne rien supprimer d'autre.
5. Choisir 3 vols selon les règles. S'il n'existe pas 3 vols européens éligibles même après recherche, en faire moins et le dire dans le résumé (jamais de vol hors Europe pour compléter).
6. **Vidéos du Google Drive de SkyElite (prioritaires)** : `bash scripts/sync-drive-footage.sh` télécharge le dossier Drive « Vidéos pour extraits/montage vidéo jet » (partagé par lien) dans `public/footage/drive/` et crée une planche d'aperçu par vidéo dans `out/footage-sheets/`. Pour chaque vidéo absente de `public/footage/drive-manifest.json`, regarder sa planche (Read) et l'y décrire : `{ "file": "footage/drive/<nom>.mp4", "duration": …, "tags": [villes, pays, thèmes : mer, montagne, ville, jet, cabine…], "segments": [{ "from", "to", "label", "tags" }] }`, en notant tout texte ou filigrane incrusté à éviter. Pour chaque vol, utiliser **une vidéo du Drive qui correspond à la destination** (même ville, sinon même pays ou même ambiance : mer, montagne, grande ville), en variant d'un jour à l'autre ; compléter avec les plans jet / cabine de `public/footage/manifest.json`. Si le téléchargement échoue (dossier plus partagé), le signaler dans le résumé et passer à l'étape suivante.
7. Extraits vidéo de la **destination** (complément, si aucune vidéo du Drive ne convient) : `node scripts/fetch-footage.mjs "<ville d'arrivée> <pays>" <slug>` télécharge depuis Pexels (licence gratuite, usage commercial autorisé ; variable `PEXELS_API_KEY`) un plan vertical de la destination dans `public/footage/pexels/`. Si le résultat est hors sujet, réessayer avec un autre terme (monument, "<ville> aerial", "<ville> old town", plage…). En option, un 2e plan du lieu de départ. Compléter avec les plans jet / cabine de `public/footage/manifest.json` s'il y en a. Montage : 3 à 5 extraits, ~12 à 18 s, en commençant par la destination. Mention en bas de la vidéo : toujours et uniquement « Images d'illustration · prix estimé HT, sous réserve de disponibilité » (fixée dans le modèle, ne rien ajouter : ni conversion de devise, ni configuration de places). Dans la légende, « 🎥 Vidéo : <auteur> / Pexels ». Sans clé Pexels ni extrait adapté : `clips: []` (fond animé) et le signaler dans le résumé.
8. Écrire `reels/batches/AAAA-MM-JJ.json` au même format que `reels/batches/2026-10-28.json` (props du modèle `EmptyLegReel` : villes, codes pays ISO, date en français, prix, places, total, appareil, durée de vol estimée, légende Instagram ; la mention du bas est fixe avec emojis, hashtags et « 📩 Plus d'infos en DM @SkyElite »).
9. `node scripts/render-reels.mjs reels/batches/AAAA-MM-JJ.json`, puis vérifier une image de chaque vidéo (`npx remotion still EmptyLegReel … --props=…`) : textes lisibles, rien qui déborde.
10. **Site de réservation** https://claude.ai/artifact/Txdkcnk49b7Ak181MakZZR : pour chaque vol utilisé (et tout nouveau vol trouvé avec prix), écrire un document dans sa collection `flights` (id `<départ>-<arrivée>-<AAAA-MM-JJ>` en minuscules) avec `from`, `fromCity`, `to`, `toCity`, `region`, `date`, `dateEnd`, `time`, `aircraft`, `seats`, `priceTotal` (prix client majoré, nombre) et `active: true`. Ne jamais y mettre l'opérateur ni sa source.
10 bis. **Site public (Netlify)** : mettre aussi à jour `site/flights.json` (même format que les documents `flights` ci-dessus, avec `id`) : ajouter chaque nouveau vol avec son prix client majoré, retirer les vols dont la date (ou `dateEnd`) est passée. Le commit de l'étape 12 déclenche la mise en ligne automatique.
11. Envoyer les 3 MP4 dans les assets de la page Reels (Artifact publish, `asset: true`, `file_paths`), puis écrire 3 documents dans la collection `reels` (id `AAAA-MM-JJ-<id>`) avec : `day`, `order`, `route`, `flightDate` (AAAA-MM-JJ), `title`, `caption`, `videoUrl` (url renvoyée par l'upload), `source`, `sourceUrl`, `price`, `footage` (chemin de la vidéo-source utilisée, ou `animation`) et `clips` (la liste des passages montés : `src`, `from`, `seconds`, `zoom`, `origin`), pour que les jours suivants puissent varier.
12. Commiter le fichier du lot, `site/flights.json` et `public/footage/drive-manifest.json` (pas les MP4) et pousser sur `emptyleg-reel`.

## Bibliothèque d'extraits (`public/footage/`)
`manifest.json` liste les extraits fournis par SkyElite :
```json
[{ "file": "footage/nice-promenade.mp4", "duration": 12.4, "tags": ["nice", "FR", "mer", "ville"] },
 { "file": "footage/jet-tarmac-1.mp4", "duration": 8.0, "tags": ["jet", "tarmac"] }]
```
Tags utiles : code IATA ou nom de ville, code pays, thème (`mer`, `montagne`, `ville`, `desert`, `neige`), et `jet`, `cabine`, `tarmac` pour les plans génériques.
Dans les props, un extrait s'écrit `{ "src": "footage/xxx.mp4", "from": 2, "seconds": 3.5 }`.
Les entrées peuvent lister des `segments` (from/to, tags, description) : choisir les extraits dans ces plages.
Avec des images propres (sans sous-titres incrustés) : mettre `"bandOpacity": 0.62` dans les props pour que la bande de prix laisse voir l'image, et pour les plans où le jet est en bas de l'image ajouter `"y": -240, "zoom": [1.28, 1.33]` à l'extrait afin de le remonter au-dessus de la bande (inutile pour les plans de cabine).
Exemple complet : `reels/batches/2026-10-28.json`.
